# agent-kit

Переносимая агентская обвязка для проектов:

- **OMO**: плагин `oh-my-openagent@4.19.4` в `opencode.json` проекта и полный
  проектный профиль `.omo/omo.jsonc`: модели 11 агентов, 8 категорий,
  резервные маршруты и runtime fallback. Глобальный `~/.omo/omo.jsonc`
  для этого профиля не нужен; [провайдеры](#провайдеры-для-omo) подключаются отдельно;
- **Mempalace** 3.9.0: локальный MCP-сервер, палата `.mempalace/palace`,
  backend `chroma`, эмбеддинги `embeddinggemma`, отдельное крыло на проект.
  Автосохранение через hooks и телеметрия по умолчанию отключены;
- **project-memory**: чистый каркас с baseline, реестрами, протоколом сессии,
  ADR-0001, CHG-0001 и шаблонами `ARCH`/`ADR`/`CHG`/`OQ`;
- **правила агентов**: короткий управляемый блок `AGENTS.md`, навыки
  `agent-kit-memory` и `agent-kit-worktrees` с подробностями по запросу,
  `scripts/agent-worktree`, команды `/memory-checkpoint` и `/memory-change`;
- **исполняемые спецификации** (компонент `spec`): проектный CLI
  [focused-spec](https://github.com/bamanoz/focused-spec) из npm по тегу `latest`.
  Его штатный `init --tools opencode` устанавливает навык и `/focused-spec`.
  Комплект не копирует workflow, не добавляет spec-инструкции в `AGENTS.md`
  или роли OMO и не навязывает формат документов и тестовый фреймворк.

## Платформы

| Платформа | Статус |
| --- | --- |
| Linux, WSL2 | Проверено |
| Windows 10/11 x64 (cmd, PowerShell) | Поддерживается; проверены разрешимость пакетов и логика установщика, живой запуск на Windows не выполнялся |
| macOS | Должно работать (те же sh-скрипты), не проверялось |
| Windows ARM64 | Не поддерживается: для chromadb нет сборок |

Проект, созданный в одной ОС, работает в другой: в `scripts/` лежат пары
`mempalace-mcp` / `mempalace-mcp.cmd`, а `opencode.json` ссылается на
`scripts/mempalace-mcp` — OpenCode в Windows сам выбирает `.cmd`. Окружение
Mempalace (`.venv-mempalace`) и палата платформенно-зависимы и в Git не
попадают: на другой машине выполните установщик повторно.

## Требования

- Python 3.12+ для окружения Mempalace (установщик ищет `python3.12+`, в
  Windows — `py -3.14…-3.12`; можно указать `--python`). Сам установщик
  запускается на Python 3.9+.
- В Linux: пакет `python3.X-venv`. В Windows: Python с python.org вместе с
  py-launcher.
- `git`, OpenCode.
- Для компонента `spec`: Node.js 22.16+ и npm; у будущего `latest` могут быть
  более высокие требования. Без подходящего Node/npm установка `spec`
  останавливается. Сейчас автоматическая установка поддерживает npm;
  проект с другим менеджером пакетов сохраняется без запуска npm.
- Для проектных тестов нужны средства текущего стека. Компонент `spec` не
  устанавливает Python, .NET SDK или тестовый фреймворк ради своей установки.
  Требования Python для установщика и Mempalace указаны выше.
- Сеть при первой установке: PyPI (~430 МБ пакетов) и Hugging Face (модель
  эмбеддингов ~300 МБ), npm для `focused-spec` и плагина OMO. Для работы
  моделей нужен доступ к API провайдеров. Для офлайн-установки см. ниже.

## Установка с вопросами

Распакуйте архив и запустите мастер:

| Система | Файл | Как запустить |
| --- | --- | --- |
| Linux, macOS, WSL | `setup.sh` | `./setup.sh` в терминале или двойной щелчок (откроется терминал) |
| Windows | `setup.cmd` | двойной щелчок или `setup.cmd` в cmd/PowerShell |

Мастер спрашивает путь к каталогу проекта (можно перетащить папку в окно),
имя проекта, крыло Mempalace, версию OMO, вид окружения и установку компонента
`spec`, показывает итог и после подтверждения разворачивает обвязку.
Если в проекте уже есть `.agent-kit.json`, мастер предлагает обновление с
прежним крылом. Если рядом
с мастером лежит каталог `wheels/` (офлайн-архив), пакеты берутся из него.

## Установка без вопросов

Linux, macOS, WSL:

```bash
tar xzf agent-kit-1.4.0.tar.gz
agent-kit-1.4.0/install.sh ~/work/new-project
agent-kit-1.4.0/install.sh ~/work/new-project --dry-run   # только показать
```

Windows (cmd или PowerShell), архив `agent-kit-1.4.0.zip`:

```bat
agent-kit-1.4.0\install.cmd C:\work\new-project
```

По умолчанию установщик выбирает оба компонента:

| Компонент | Состав | Как пропустить |
| --- | --- | --- |
| `base` | OMO, профиль моделей, Mempalace, project-memory и правила агентов | Выбрать другие компоненты через `--only` |
| `spec` | focused-spec@latest, штатный навык и команда `/focused-spec` | `--no-spec` |

Параметры: `--name`, `--wing`, `--omo <пакет[@версия]|none>`, `--venv shared|local`,
`--venv-dir`, `--python`, `--wheelhouse <каталог>`, `--no-mempalace`,
`--no-omo-profile`, `--no-spec`, `--only <base,spec>`,
`--skip-probe`, `--dry-run`. В `--only` передается нужный список через запятую;
он имеет приоритет над `--no-spec`. Пропуск компонента при
обновлении не удаляет его ранее установленные файлы.

`--no-omo-profile` пропускает профиль моделей из `base`, оставляя выбор
моделей личному глобальному конфигу; `--omo none` пропускает и профиль, и
добавление плагина OMO. Компонент `spec` не добавляет роли в `.omo/omo.jsonc`.
Для установки только базовой обвязки используйте `--only base`.

Только focused-spec — для проекта со своей обвязкой:

```bash
agent-kit-1.4.0/install.sh ~/work/project --only spec
```

Справка: `install.sh --help` / `install.cmd --help`.

## Что происходит при установке

| Объект | Поведение |
| --- | --- |
| `project-memory/`, `.omo/rules/` | Создаются, если файла нет; существующие не трогаются |
| `scripts/*`, `.opencode/commands/memory-*.md`, `.opencode/skills/agent-kit-*/` | Управляются комплектом: обновляются с резервной копией |
| `AGENTS.md`, `.gitignore`, `.gitattributes` | Вставляется или обновляется блок между маркерами `agent-kit`; остальной текст, BOM и переводы строк сохраняются |
| `opencode.json` | Добавляются отсутствующие `mcp.mempalace` и плагин OMO; ручные настройки не меняются, прежний прямой запуск MCP переводится на `scripts/mempalace-mcp`. При наличии `opencode.jsonc` настройки для ручного слияния выводятся в терминал |
| `.venv-mempalace` | Ссылка на общее окружение (Linux: `~/.local/share/agent-kit/venvs/mempalace-3.9.0`, Windows: `%LOCALAPPDATA%\agent-kit\venvs\mempalace-3.9.0`; в Windows при отсутствии прав на symlink создается junction) или локальное окружение при `--venv local` |
| `.mempalace/palace`, `mempalace.yaml` | Создаются при первой установке; в палату пишется первая запись в комнату `implementation-overview`. Глобальный `~/.mempalace/known_entities.json` не изменяется |
| `.opencode/skills/focused-spec/SKILL.md`, `.opencode/commands/focused-spec.md` | Создаются штатным `focused-spec init`. Перед записью выполняется dry-run; изменённые пользователем интеграции не заменяются. Штатные файлы прежнего пакета обновляются с backup |
| `.focused-spec/runners/` | При установке не создаются; существующие реализации не удаляются и не перезаписываются |
| `.omo/omo.jsonc` | `base`: профиль моделей. Отсутствующие ключи добавляются рекурсивно, значения проекта имеют приоритет. При изменении сохраняется backup; комментарии прежнего JSONC остаются в нём. Компонент `spec` этот файл не меняет |
| `.focused-spec/config.yaml`, `specs/` | При чистой установке не создаются. Формат, runner и конфигурацию выбирают под задачу через штатный навык; существующие evidence и документы автоматически не мигрируются |
| `package.json`, `package-lock.json` | `spec`: зависимость `focused-spec` объявляется как `latest`, при каждой установке разрешается свежий релиз и обновляется локальный пакет. Lock хранит точную установленную версию. Скрипты `spec:validate` и `spec:run` добавляются, если отсутствуют; пользовательские скрипты сохраняются |
| `.agent-kit.json` | Имя проекта, крыло, версии и установленные компоненты; повторная установка берет крыло отсюда |

После установки скрипт запускает MCP-сервер так же, как OpenCode, и
проверяет `tools/list`, запись и поиск в крыле проекта. Для `spec` проверяются
идентичность пакета, контракты CLI, отчёт `init`, установленные файлы и выдача
workflow через `instructions`. Установщик не запускает проектные тесты,
`validate` или `run` и не объявляет установку доказательством приёмки.
`--skip-probe` отключает MCP-проверку и повторное получение workflow после
`init`, но не предварительные проверки безопасности и совместимости `spec`.
`--no-mempalace` пропускает создание окружения и палаты; файлы запуска и
настройки MCP остаются частью `base`.

## Профиль OMO и доступ к моделям

Профиль задает основные модели, уровень reasoning, резервные маршруты
агентов и категорий и автоматическое переключение при сбоях (runtime fallback).
Профиль находится в `template/omo/profile.json`; установщик добавляет его
в `.omo/omo.jsonc` с приоритетом значений, уже заданных проектом. Личный
глобальный файл не изменяется. Повторная установка не заменяет существующие
массивы маршрутов. Дополнения ролей для focused-spec не устанавливаются.

В профиле используются идентификаторы провайдеров `apiclo`, `externcash`,
`closerouter`, `closerouter-anthropic` и `codexsale`. Конфигурация этих
провайдеров в OpenCode и ключи доступа в комплект не входят: получатель должен
настроить их и авторизоваться через `opencode auth login` либо заменить
маршруты в `.omo/omo.jsonc` своими. Один профиль не создаёт доступ к моделям.
После установки перезапустите OpenCode и используемый `opencode serve`.

## Изоляция данных

Записи, граф знаний и события каждого проекта хранятся в его
`.mempalace/palace`. Общими остаются `~/.mempalace/` (журнал операций без
текста записей, реестр сущностей, настройки по умолчанию), окружение
Mempalace и кэш модели эмбеддингов.

## Офлайн-установка Mempalace

```bash
./build.sh --with-wheels windows   # или linux; Python 3.12, x64
```

В `dist/` создаются архивы
`agent-kit-1.4.0-offline-<платформа>-py312.tar.gz` и `.zip`. Внутри находится
каталог `agent-kit-1.4.0/` с `wheels/`:

```bat
agent-kit-1.4.0\install.cmd C:\work\project --wheelhouse agent-kit-1.4.0\wheels --python "C:\Program Files\Python312\python.exe"
```

Модель `onnx-community/embeddinggemma-300m-ONNX` скачивается в кэш Hugging
Face при первом обращении; для машины без сети скопируйте каталог кэша
(`~/.cache/huggingface` или `%USERPROFILE%\.cache\huggingface`) заранее.
Архив включает только Python-зависимости Mempalace. Пакеты npm для OMO и
focused-spec нужно подготовить отдельно; `--wheelhouse` их не устанавливает.

## Обновление проекта

Запустите установщик новой версии для того же каталога. Проектные файлы и
палата сохраняются, управляемые блоки и скрипты обновляются с резервными
копиями `*.bak-<время>` (исключены из Git).

## Исполняемые спецификации (focused-spec и SDD)

Компонент `spec` устанавливает локальный CLI и запускает штатный
`focused-spec init --tools opencode`: он создаёт навык-загрузчик и команду
`/focused-spec`. Загрузчик получает актуальный workflow из того же проектного
CLI отдельным вызовом `instructions --protocol 1 --topic workflow --json`.
Комплект не встраивает workflow в навык, `AGENTS.md` или роли OMO.

При чистой установке `.focused-spec/config.yaml`, `specs/` и runner'ы не
создаются. Обычные задачи выполняются обычным порядком; для работы по
спецификации используйте `/focused-spec`. Формат, конфигурацию и runner
выбирают под задачу по инструкциям локального CLI, с учётом стека, менеджера
зависимостей и тестового фреймворка проекта. Для inline-сценариев Markdown
можно выбрать официальный `@focused-spec/format-inline`; он не устанавливается
заранее, как и остальные адаптеры. Его настройку берут из актуальных инструкций
локального CLI и документации выбранного пакета.

При каждой реальной установке `spec` тег `latest` разрешается через npm
registry. Полученная точная версия используется для проверки и установки
на время одной операции. В `package.json` остаётся `latest`, а lock-файл
хранит точную установленную версию для воспроизводимости.

Штатные файлы навыка и команды обновляются с резервной копией. Изменённые
пользователем skill/command не заменяются: конфликт требует ручного решения.
При несовместимости нового CLI с активной конфигурацией или контрактами
адаптеров обновление останавливается до изменения зависимостей.
Конфигурация, runner'ы, evidence и документы проекта остаются нетронутыми.

`--dry-run` не обращается к сети и не меняет файлы; при совместимом локальном
CLI и существующем каталоге проекта выполняет штатный preview. Полная проверка
нового `latest` выполняется при реальной установке.
При реальной установке новый пакет проверяется во временном каталоге до
изменения зависимостей проекта: проверяются контракты, workflow и полный
отчёт `init --dry-run --json` для обоих файлов интеграции. При совместной
установке `base,spec` эта проверка и проверка Node/npm предшествуют записи
файлов `base`. Перед записью интеграции preview повторяется.

## Разработка и сборка комплекта

```bash
./dev/check.sh
./build.sh
```

`dev/check.sh` устанавливает `focused-spec@latest` через npm в
`dev/node_modules` и запускает `unittest`: установка и повторное обновление,
сохранность пользовательских файлов, резервные копии, dry-run, бюджет строк
AGENTS.md, слияние OMO и реальный CLI во временных проектах.
Нужны Node.js 22.16+, npm и Python 3.9+; установка и интеграционные проверки
обращаются к npm registry.

`build.sh` создает `dist/agent-kit-1.4.0.tar.gz` и
`dist/agent-kit-1.4.0.zip`. Зависимости разработки и тестовый скрипт из `dev/`
в архивы не входят. Версия архивов берется из `KIT_VERSION` в `lib/kit.py`.
