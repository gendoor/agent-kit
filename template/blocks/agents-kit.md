## Агентская обвязка agent-kit

Блок управляется `agent-kit` {{KIT_VERSION}}. Проектные правила пиши вне блока;
при конфликте они имеют приоритет над общими правилами ниже.

## Язык кода и артефактов

- Комментарии, docstring, диагностику, исключения, логи и assertion-сообщения
  пиши на русском в новом и содержательно изменяемом коде. Не переводи
  идентификаторы, контрактные значения, вывод внешних инструментов; не меняй
  незатронутый или сгенерированный код ради перевода.
- Передавай эти правила исполнителям и проверяй результат. Язык коммитов —
  по конвенциям проекта.

## Окружение и согласованность

- Определи стек по манифестам, lock-файлам и CI; используй его инструменты
  и тестовый фреймворк. Недостающие проектные зависимости готовь штатно,
  по мере задачи и в рамках разрешений, предпочтительно в изолированной среде.
- Не обновляй версии без необходимости, не устанавливай системные SDK и не
  повышай права без разрешения. При блокере сообщи точную причину; не подменяй
  реальные проверки заглушками или другим стеком.
- Меняя структуру, конфигурацию или workflow, синхронизируй README, инструкции,
  примеры, справку и defaults. Проверяй только установленные компоненты;
  ищи старые пути и названия, но не переписывай историю и архивы.
- `.omo/omo.jsonc` задаёт проектные маршруты, но не авторизацию провайдеров.
  Не заменяй маршруты без задачи. После изменения настроек или навыков
  перезапусти OpenCode и используемый `opencode serve`.

## Project Memory

- Код, тесты и машинные контракты определяют фактическое поведение;
  `project-memory/` в Git — baseline, архитектуру, решения и контракты;
  согласованные требования — целевое поведение. Mempalace объясняет историю
  и причины, но не переопределяет Git и не заменяет точную спецификацию.
- Перед изменением целевой кодовой базы прочитай и выполняй
  `project-memory/session-protocol.md`: baseline, карту компонентов, активные
  CHG/ADR, контракты и релевантные комнаты памяти сверяй с кодом.
- Существенные изменения оформляй CHG, при необходимости ARCH/ADR; прежние
  решения помечай `SUPERSEDED` со ссылкой. Уровни baseline обновляй независимо
  и только по факту; после существенной сессии синхронизируй Git и checkpoint.

### Mempalace

- Перед поиском, сохранением или настройкой памяти загрузи навык
  `agent-kit-memory` (либо прочитай `.opencode/skills/agent-kit-memory/SKILL.md`).
- Крыло: `{{WING}}`; агент: `opencode`. Только локальная `.mempalace/palace`,
  backend `chroma`; MCP/CLI — через `scripts/mempalace-mcp` и `scripts/mempalace`
  (Windows: `.cmd`), не напрямую через venv. Автосохранение выключено.
- Не сохраняй секреты и чувствительные данные, сырой диалог или полный diff;
  не индексируй целиком закрытые каталоги и сгенерированные артефакты.

## Subagent Workspace Isolation

- Перед write-делегацией загрузи `agent-kit-worktrees` (либо прочитай
  `.opencode/skills/agent-kit-worktrees/SKILL.md`). Параллельные изменения
  существующих файлов — только в отдельных worktree; merge выполняет главный
  агент последовательно. Не меняй файлы вне выданного workspace.
- Read-only задачи допустимы параллельно. Create-only без worktree — только
  с явными непересекающимися новыми путями; общие точки регистрации меняет
  главный агент. Один write-субагент может работать в основном workspace.
- Проверяй содержательность и полноту каждого результата. Ошибка, обрыв или
  пустой ответ — не успех: повтори задачу, при повторной неудаче выполни сам
  и сообщи об ограничении. При лимите concurrency повторяй последовательно.
