# Изоляция исполнителей

Навык управляется agent-kit {{KIT_VERSION}}. Не запускай параллельно несколько
субагентов, изменяющих существующие файлы в одном workspace: записи могут
перезаписать друг друга даже при логически разных задачах.

## Выбор режима

- Read-only задачи можно запускать параллельно в пределах concurrency.
- Параллельный create-only без worktree допустим только с явными
  непересекающимися списками новых путей. Проверь, что пути не существуют;
  запрети любые изменения существующих файлов. Общие точки регистрации
  (`.sln`, `.csproj`, манифесты, индексы) меняет главный агент последовательно.
- Один write-субагент без других параллельных write-делегаций может работать
  в основном workspace. Главный агент не должен одновременно менять его файлы.
- Для нескольких параллельных write-задач создай отдельный git worktree
  каждому исполнителю. Выдай точный рабочий каталог и запрети запись вне него.
  Передай контракты, критерии приёмки, проектные правила и команды проверок.

## Команды

В Windows используй `scripts\agent-worktree` с теми же аргументами.

```bash
scripts/agent-worktree create <task-name>
scripts/agent-worktree list
scripts/agent-worktree diff <task-name>
scripts/agent-worktree merge <task-name>
scripts/agent-worktree remove <task-name>
```

`create` готовит `.worktrees/<task-name>` на ветке `agent/<task-name>`;
`diff` показывает изменения относительно базы; `merge` выполняет `--no-ff`;
`remove` удаляет worktree и ветку. Перед применением проверь справку скрипта
и состояние Git. `.worktrees/` исключён из Git.

## Приёмка и слияние

- Проверяй не только статус делегации, но и содержательность результата,
  diff, контракты и фактически выполненные проверки.
- Пустой ответ, ошибка, обрыв или отсутствие запрошенного итога — не успех.
  Перезапусти задачу с требованием вернуть итог и диагностику; при повторной
  неудаче выполни сам и сообщи об ограничении. При лимите concurrency повторяй
  незавершённые задачи последовательно.
- Merge выполняет только главный агент, последовательно, по одному worktree,
  при чистом основном дереве. Изменения должны быть закоммичены в ветке;
  коммиты и merge делай только при разрешении пользователя на эти действия.
- После merge выполни сборку и тесты затронутых систем. При конфликте остановись
  и разреши его с приоритетом контрактов и `project-memory/`; не затирай
  пользовательские изменения. Не обходи проверку чистоты основного дерева.
- После успешной интеграции удали worktree штатной командой `remove` только
  когда нет несохранённых результатов и разрешено удаление ветки.
